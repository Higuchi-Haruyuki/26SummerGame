## Object-Component

- `Scene`が`Object`を`shared_ptr`で所有し、`Object`が`Component`を`shared_ptr`で所有する階層構造にしている。
  - `Object`から`Scene`、`Component`から`Object`への逆方向の参照には`weak_ptr`を使用する。
  - これにより循環参照を防ぎ、参照先が既に破棄されている場合も`lock()`によって安全に確認できる。
  - `Scene`は`std::vector`で`Object`を、`Object`は`std::vector`で`Component`を保持する。

- ゲームループでは、`Scene`から`Object`の`Init`、`Update`などの仮想関数を呼び出し、`Object`から各`Component`の対応する処理を呼び出す。
  - 共通インターフェースを通して異なる`Object`や`Component`を統一的に処理できる。

- `Object`や`Component`の追加・削除は、その場では行わず遅延実行する。
  - `Update`中に追加・削除要求を記録し、`Update`のループ終了後、`Draw`処理に入る前に反映する。
  - `std::vector`を走査している最中に要素数や内部配置が変化し、イテレータや参照が無効化されることを防ぐ。

## Camera

- プレイヤーの操作性を考慮し、自由に視点を操作できるフリーカメラを実装している。

- カメラの現在値と目標値を分けて保持し、指数平滑によって補間する。
  - 目標値が変化し続ける場合でも滑らかに追従できる。
  - 目標との差が大きいときは大きく移動し、目標に近づくほど移動量が小さくなるため、急停止感の少ない自然なカメラ挙動になる。

## UI

- UIを親子関係のある階層構造として管理し、親UI要素が子UI要素を所有する。

- ゲームの状態と表示するUIパネルをテーブルで対応付けし、現在の状態に応じて各パネルの可視・非可視を切り替える。
  - UIの表示制御を個別の条件分岐ではなく、状態とパネルの対応関係として管理できる。

- マウスカーソルとのヒット判定は、表示されているUI要素に対してのみ行う。
  - 親UI要素から子UI要素へ階層的にヒット判定を呼び出す。
  - 非表示UIへの不要な判定を避けるとともに、UI階層に沿った入力処理ができる。

## 工業オブジェクト周辺のComponent設計

- 工業設備が持つ機能を複数のComponentへ分割し、組み合わせによって設備の挙動を構成している。

主なComponentは以下。

- `TransportSystem`
  - アイテム搬送を担当する。

- `ManufacturingSystem`
  - レシピに基づく素材消費や製造処理を担当する。

- `FuelSystem`
  - 燃料の保持・消費など、燃料を必要とする設備の処理を担当する。

これらを設備ごとに必要な組み合わせで利用することで、各設備クラスへ同じ処理を重複して実装することを避け、機能の再利用性を高めている。

## GameResource

- ゲーム開始時に必要なリソースをまとめてロードし、ゲーム全体で利用するリソースの管理を1クラスへ集約している。

- 各リソースには一意な列挙型のIDを割り当て、そのIDとDxLibのリソースハンドルを対応付けて保持する。

- 利用側はDxLibのハンドルを直接管理せず、リソースIDを指定して必要なリソースを取得する。

これにより、

- 同一リソースの重複ロードを防止できる。
- リソースのロード・取得・解放方法を一か所へ集約できる。
- 利用側がファイルパスやDxLibのハンドル管理を意識する必要がなくなる。

- ゲーム終了時には保持しているリソースを走査し、まとめて解放する。

## Input

- キーボードやゲームパッドなどの物理入力を、ゲーム内の「アクション」として抽象化している。

例えば利用側は、

`Spaceキーが押されたか`

ではなく、

`Interactアクションが実行されたか`

という形で入力を取得できる。

これにより、

- ゲームロジックと具体的な入力デバイスを分離できる。
- キーバインドを変更してもゲーム側の処理を変更する必要がない。
- キーボードとゲームパッドなど、複数デバイスを同じゲームアクションへ対応付けやすくなる。

## Event

- 1つのイベントに対して複数の関数を購読できるイベントシステムを実装している。

- イベント購読時に`Connection`を取得し、その`Connection`の寿命とイベント購読の寿命を紐付けている。

- `Connection`がスコープを抜けて破棄される際、自動的にイベント購読を解除するRAII形式の設計としている。

これにより、

- 手動で購読解除する処理を書き忘れにくい。
- 既に破棄されたオブジェクトにイベントが送られるリスクを減らせる。
- C++のオブジェクト寿命を利用してイベント購読の寿命も管理できる。
